# Activity Channel Dataverse backend

Isolated signed .NET Framework 4.6.2 Sandbox/Database plugin, version 1.0.0.0. No dependencies beyond Dataverse SDK and framework assemblies. Administrative helpers compile separately and are never included in the runtime DLL.

Run `powershell -NoProfile -ExecutionPolicy Bypass -File backend/activityChannel/build-test.ps1` from the repository root. The script uses the existing local PAC SDK tools convention and writes only ignored workspace build output under `../.superpowers/activity-channel-build`; it signs/verifies the runtime, runs behavioral SDK fake tests, and compiles administrative helpers.

The fixed action is `mss_ActivityChannelCommand`; inputs are required ActorContactId Guid, Command String, Payload String; output Result String. Execute privilege is `prvReadmss_ActivityPost`. The plugin obtains its organization service using context.UserId. Only the trusted ServerLogic bridge may provide ActorContactId; browser credentials and selectable actor inputs are outside this boundary.

Commands: feed, comments, post, comment, reply, pin, unpin, remove; trusted bridge-only count with exact empty payload `{}`. Payload keys are exact and required. All responses use the approved DTO contract, `ok:true` on success, or a sanitized error with unauthenticated/forbidden/validation/not_found/conflict/unavailable code. Contact eligibility requires active, login-enabled and a local or external portal identity; functional approval is intentionally not checked. Moderation queries the exact current site's Administrator membership. Author display queries only fullname/jobtitle. Missing authors receive an honest null-ID fallback.

Posts use mss_content; comments use mss_commenttext with both mss_activitypost and immediate mss_parentcomment on replies. Bodies preserve paragraph/whitespace data, reject blank input and exceedance of 8000 UTF-16 code units. Render this plain text safely in clients. Standard timestamps are retrieved after persistence. Authors, generated internal names, false pin state and moderation fields are server-owned. Conditional UpdateRequest/DeleteRequest enforce row versions; native cascade performs dependent comment deletion after the separately approved schema change.

Create IDs are first 16 SHA256 bytes of UTF8 `activity-channel:<command>:<actor-D>:<requestId-D>`, interpreted using Guid(byte[]) with byte 7 version nibble 5 and byte 8 RFC variant bits. Query-before-create avoids catching write faults in an aborted SDK transaction. Exact matching actor/body/post/parent replays succeed. Concurrent first attempts can return unavailable if a native duplicate-key write fails; retry the SAME requestId to recover. Never generate a new requestId on uncertain saves.

Feed queries active pinned and regular streams separately (20 each, transition at most 40), stable sort ties by ID, and include false/null flags in regular. Comment reads use at most 40 IDs, 100 records/page, active post join, createdon/ID ascending. Page numbers are bounded 1..2500; MoreRecords at page 2500 returns unavailable rather than an unusable cursor; offset-based navigation has normal live-update drift, so clients deduplicate and refresh after moderation. Raw feed never executes an aggregate and returns totalCount:null/countUnavailable:true placeholders. The bridge invokes count in a separate Custom API transaction and enriches the unchanged browser feed DTO. Count uses FetchXML aggregate, returns `{ok:true,totalCount:number}`, and returns unavailable on SDK failure through the outer handler with no subsequent SDK reads. No all-body download counting occurs.

Administrative integration (no remote operations occur during build/tests):

- `RegisterActivityChannelCommand.Apply(service, dllPath, outputPath)` validates existing registration before updating, and creates required members in CRMSolution with Sandbox/Database isolation and fixed privilege.
- `ApplyActivityChannelSchema.Apply(service, outputPath)` validates the actual unmanaged customizable memo and relationship metadata ID. It accepts only memo 100/8000 and Delete RemoveLink/Cascade, changes only those approved settings, preserves other retrieved cascade/customizability values, adds the two affected entity components to CRMSolution, publishes only those entities, and verifies read-back before writing its sanitized before/after output.

The caller MUST supply the existing authenticated fixed-UAT helper guard for environment 16838866-275a-e2e7-838f-57313f30a416 / https://org97063a46.crm.dynamics.com. Never invoke against Production. `scripts/activity-channel/schema-manifest.json` is an explicit planned-state descriptor, not evidence of remote application; the Apply output is the execution evidence. Schema application itself deletes no records; future post deletes use the approved native cascade. The self-parent relationship is not modified.
