# Meeting Report attachment history: scoped decision

The existing report attachment service calls a separate Power Automate flow directly. Successful annotation writes arrive under the flow identity and do not establish which portal Contact initiated the upload/deletion. Reported By, annotation Created By and current owner are not reliable substitutes. Existing source/storage behavior is preserved in the current Activity Log implementation; no upload actor is invented.

To cover these operations reliably requires this exact additional scope:

1. Add a small Activity Log receipt endpoint. It derives the Contact from Server.User, verifies the existing report/attachment write permissions, and obtains a short-lived signed receipt bound to this website, actor, report, action and individual file/attachment. Include expected byte count and SHA-256 for uploads. Never accept the actor or occurrence time from the browser.
2. In the existing `meetingReportAttachmentService.ts`, request receipts and include them in the existing flow request. Keep the upload storage, report/annotation associations, file limits, names, MIME handling, success response parsing and visible form controls unchanged. An inability to obtain a verified receipt is a real additional dependency that must be resolved explicitly; it must not produce fabricated successful history.
3. In the existing UAT report-attachment flow, propagate the receipt into private completion context. Upload: preserve the receipt with the newly committed annotation; deletion: record the validated deletion receipt before the actual delete so an asynchronous preimage retains the acting user. Do not infer deletion actor from the original uploader. Ignore view/download operations.
4. A separate asynchronous observer validates the signature, target, action, expiry and actual persisted attachment metadata/content hash before producing Uploaded/Deleted. Event identity is the receipt's stable operation ID. Failed and repeated transfers do not manufacture additional successful events. Keep receipt/token values out of Activity Log DTOs, details, normal logs and download controls.
5. Keep signing material only in trusted native secure configuration. No new source-record schema column or replacement storage is proposed. Export/inspect the actual UAT flow before producing a guarded patch; preserve its original exact export for rollback. Native auditing and Production remain untouched.

This extension has NOT been applied. Options: authorize this isolated receipt/flow integration; or release the page and currently provable module logging while clearly excluding Meeting Report attachment Uploaded/Deleted entries until a later extension. This is the only currently identified external write path without trustworthy actor propagation. Direct Power Pages Web API paths and native server commands still require their own hosted identity proof before activation.
